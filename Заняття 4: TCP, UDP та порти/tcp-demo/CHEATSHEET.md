# Шпаргалка: живе демо TCP (Тема 4. TCP, UDP та порти)

Файли в `tcp-demo/`:

| Файл | Що робить |
|---|---|
| `server.py` | TCP-сервер на 127.0.0.1:9000, друкує `Connected: (ip, port)` і `отримано N байтів` |
| `client.py` | підключається, надсилає `--count` разів по `--size` байтів з паузою `--delay` |
| `run_demo.sh` | усе демо однією командою (Linux/macOS) |
| `annotate.py` | прибирає `options [...]`, нумерує рядки, додає пояснення |
| `expected_output.txt` | реальний вивід (Linux і macOS): запасний слайд |

---

## 1. Варіант А: одна команда

```bash
cd tcp-demo
./run_demo.sh
```

Скрипт сам вибирає інтерфейс (`lo` на Linux, `lo0` на macOS), запускає tcpdump (за потреби
запитає пароль sudo), сервер і клієнт, потім друкує пояснений вивід і зберігає:
- `capture.txt`: текстовий вивід tcpdump;
- `capture.pcap`: той самий трафік для Wireshark.

Варіації:
```bash
./run_demo.sh --count 5 --size 50 --delay 0.5   # аргументи передаються client.py
PORT=9100 ./run_demo.sh                         # інший порт
```

## 2. Варіант Б: вручну, у трьох терміналах (наочніше для студентів)

**Термінал 1: захоплення** (запустити першим):
```bash
sudo tcpdump -i lo  -n -t -l 'tcp port 9000' | tee capture.txt    # Linux
sudo tcpdump -i lo0 -n -t -l 'tcp port 9000' | tee capture.txt    # macOS
```
Ключі: `-i`: інтерфейс, `-n`: без DNS-імен, `-t`: без часу, `-l`: рядок одразу на екран.

**Термінал 2: сервер:**
```bash
python3 server.py
```

**Термінал 3: клієнт:**
```bash
python3 client.py --count 3 --size 100 --delay 1
```

Після завершення клієнта: `Ctrl+C` у терміналі 1, потім:
```bash
python3 annotate.py capture.txt
```

Порядок важливий: **tcpdump → сервер → клієнт**. Якщо клієнт стартує до сервера,
буде `ConnectionRefusedError` (і в tcpdump видно `[S]` → `[R.]`).

## 3. Очікуваний вивід (Linux, реальний запуск)

```
 1. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [S], seq 3367329132, win 65495, length 0                   ← SYN
 2. IP 127.0.0.1.9000 > 127.0.0.1.57558: Flags [S.], seq 3941166584, ack 3367329133, win 65483, length 0  ← SYN-ACK (ack = seq + 1)
 3. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [.], ack 1, win 512, length 0                              ← ACK: рукостискання завершено
 4. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [P.], seq 1:101, ack 1, win 512, length 100                ← байти 1–100
 5. IP 127.0.0.1.9000 > 127.0.0.1.57558: Flags [.], ack 101, win 511, length 0                            ← «чекаю байт 101»
 6. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [P.], seq 101:201, ack 1, win 512, length 100              ← байти 101–200
 7. IP 127.0.0.1.9000 > 127.0.0.1.57558: Flags [.], ack 201, win 511, length 0                            ← «чекаю байт 201»
 8. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [P.], seq 201:301, ack 1, win 512, length 100              ← байти 201–300
 9. IP 127.0.0.1.9000 > 127.0.0.1.57558: Flags [.], ack 301, win 511, length 0                            ← «чекаю байт 301»
10. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [F.], seq 301, ack 1, win 512, length 0                    ← FIN: клієнт закриває свій напрям
11. IP 127.0.0.1.9000 > 127.0.0.1.57558: Flags [F.], seq 1, ack 302, win 512, length 0                    ← FIN+ACK: сервер підтверджує FIN і теж закриває
12. IP 127.0.0.1.57558 > 127.0.0.1.9000: Flags [.], ack 2, win 512, length 0                              ← ACK на FIN: з'єднання закрито

Підсумок: рукостискання — 3, дані — 3, ACK — 3, закриття — 3
```

Вивід сервера:
```
Сервер слухає 127.0.0.1:9000
Connected: ('127.0.0.1', 57558)
отримано 100 байтів
отримано 100 байтів
отримано 100 байтів
Клієнт закрив з'єднання, сервер завершує роботу
```

Номери seq у рядках 1–2 і порт клієнта щоразу інші, а структура та сама.

### Відносні й абсолютні номери

- За замовчуванням tcpdump показує **абсолютні** seq/ack лише в `[S]` і `[S.]`, а далі
  **відносні** (від початку потоку). Тому в рядку 3 `ack 1`, а дані йдуть як `seq 1:101`.
  Це найкраще збігається зі слайдами.
- З ключем `-S` усі номери абсолютні (напр. `seq 3367329133:3367329233`). Можна показати,
  що «1» насправді означає ISN + 1:
  ```bash
  tcpdump -n -t -S -r capture.pcap | python3 annotate.py
  ```

### Якщо демо на macOS: вивід трохи інший (це нормально)

Реальний запуск на macOS (див. `expected_output.txt`) має **14 рядків** замість 12:
- **рядок 4**: зайвий `[.] ack 1` від сервера одразу після рукостискання. Це
  «оновлення вікна» (window update): сервер повідомляє розмір буфера, нових даних немає;
- **закриття з 4 окремих кроків**: `ack 301` → `ack 302` (ACK на FIN) → `[F.]` сервера →
  `[.] ack 2`. macOS не об'єднала ACK і FIN, тому видно класичне «чотирикрокове» закриття.

Обидва варіанти правильні: це різні реалізації стеку TCP. Якщо хочете точно як на слайдах,
покажіть Linux-вивід з `expected_output.txt` або запустіть демо в Docker
(потрібен інтернет для `apt-get`):
```bash
docker run --rm -it -v "$PWD":/demo -w /demo python:3.12-slim \
  bash -c "apt-get update -qq && apt-get install -y -qq tcpdump >/dev/null && ./run_demo.sh"
```

## 4. Що сказати вголос

1. **Рядки 1–3: рукостискання.** SYN (seq = x) → SYN-ACK (seq = y, ack = x + 1) → ACK (ack = y + 1).
   ack = seq + 1, бо **SYN займає один номер** послідовності, хоча байтів не несе.
   Клієнт: SYN-SENT → ESTABLISHED; сервер: LISTEN → SYN-RECEIVED → ESTABLISHED.
2. **`length 0` у рукостисканні та в «чистих» ACK.** Дані несуть лише сегменти `[P.]`
   (`length 100`). ACK-сегмент тільки підтверджує.
3. **ACK = seq + length = наступний очікуваний байт.** `seq 1:101, length 100` означає
   байти 1–100; відповідь `ack 101` означає «маю все до 100, чекаю 101». Далі 201, 301,
   точно як на слайді.
4. **Закриття.** Клієнт: FIN (`seq 301`). Сервер: `ack 302`, бо **FIN теж займає один номер**.
   На Linux сервер одразу додав свій FIN у той самий сегмент (FIN+ACK), бо йому вже нічого
   надсилати. Тому сегментів 3, а не 4. Кожен напрям закривається **окремо**.
5. **Порт клієнта.** Покажіть на рядок `Connected: ('127.0.0.1', 57558)` у виводі сервера
   і на той самий номер у tcpdump: «Зверніть увагу: тут не 9000». **Поки не пояснюйте,**
   це відповідь на наступну вправу.

**Додатково (наприкінці):** клієнт на порт, де ніхто не слухає:
```bash
sudo tcpdump -i lo0 -n -t -l 'tcp port 9001'     # термінал 1 (lo на Linux)
python3 client.py --port 9001                    # термінал 3
```
Видно `[S]` → `[R.]` (RST): порт закритий, з'єднання не встановлено.
Клієнт друкує: `Порт 9001 закритий: сервер відповів RST`.

**Чому клієнт шле дрібними порціями з паузами:** MSS на loopback великий (≈ 65 KB на Linux,
16 344 байти на macOS), тож один `sendall` на 300 байтів був би **одним** сегментом.
`TCP_NODELAY` вимикає алгоритм Нейгла, а `time.sleep` гарантує, що кожен `send` піде окремим
сегментом.

## 5. Wireshark

1. Захоплення на loopback: Linux `lo`, macOS `Loopback: lo0`, Windows `Adapter for loopback traffic capture`.
   Або просто відкрийте готовий `capture.pcap` (File → Open).
2. Фільтр відображення: `tcp.port == 9000`, потім Enter.
3. **Statistics → Flow Graph**: увімкнути **«Limit to display filter»**, Flow type: **TCP Flows**.
   Буде діаграма зі стрілками між клієнтом і сервером, як на слайді з рукостисканням.
4. Абсолютні номери: **Edit → Preferences → Protocols → TCP** (на macOS:
   **Wireshark → Preferences…**), вимкнути **«Relative sequence numbers»**. Щоб повернути
   «1, 101, 201», увімкніть знову.

## 6. Windows

tcpdump немає. Використовуйте **Wireshark** з **Npcap**: під час встановлення Npcap
позначте «Support loopback traffic capture». У Wireshark виберіть інтерфейс
**Adapter for loopback traffic capture**, фільтр `tcp.port == 9000`.
Сервер і клієнт запускаються так само (`python server.py`, `python client.py`), у двох вікнах
PowerShell. `run_demo.sh` і `annotate.py` для живого захоплення на Windows не потрібні.
Порядок і склад сегментів (особливо при закритті) можуть відрізнятися від Linux.
Заздалегідь перевірте, що буде на вашому ноутбуці.

## 7. Якщо щось пішло не так

| Симптом | Причина / що робити |
|---|---|
| `OSError: [Errno 48/98] Address already in use` | Порт ще зайнятий (старий сервер живий або попереднє з'єднання не дозакрилось). Зачекайте кілька секунд, закрийте старий `server.py` (`Ctrl+C`), або інший порт: `python3 server.py 9100` + `python3 client.py --port 9100` (або `PORT=9100 ./run_demo.sh`). |
| `tcpdump: ... Permission denied` / `You don't have permission` | tcpdump потребує прав: запускайте через `sudo`. На macOS з установленим Wireshark (група `access_bpf`) sudo не потрібен, і `run_demo.sh` це враховує сам. |
| tcpdump нічого не показує | Неправильний інтерфейс: `lo` на Linux, `lo0` на macOS (`tcpdump -D` покаже список). Також перевірте, що фільтр і порт збігаються з портом сервера. |
| `ConnectionRefusedError` / «Порт закритий» у клієнта | Сервер не запущено або він на іншому порту. Спершу `server.py`, потім `client.py`. |
| Живе демо не працює взагалі | Відкрийте `expected_output.txt` (запасний слайд) або `capture.pcap` у Wireshark. |
